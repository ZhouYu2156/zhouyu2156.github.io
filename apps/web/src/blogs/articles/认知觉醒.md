# 写作

## 001. 如何突破技术瓶颈？

现在对我过往的学习做个深入的总结和思考吧。

在过去的这几年了，我一直在学习各种各样的技术，涵盖的领域非常广泛，包括但不限于前端、后端、爬虫、数据分析、图形化、3D、人工智能、新媒体等等，看似学了很多，实则没有一个能说得上是精通的。

总的来说，对某一门技术顶多算是熟练使用，可能还算不上。因为自己学得越多，越明白自己的几斤几两，也对自己底层知识的匮乏，诚惶诚恐。

现在很多互联网技术都是基于底层技术或者别人的框架进一步封装的，目的都在于解决团队或者开发者自己遇到的技术痛点问题，所以说学这么多别人封装出来的技术有什么用呢？没有多大的作用！

或许你学了某一门技术后，做开发更轻松了，或者学到了它的某一种设计思想，不可否认的是，这些确实给你带来了表面上的便捷与启发，但是真正有价值的，不是你学会了能够使用多少门技术，而是深入技术背后掌握它底层的设计方法和原理，知其然更要知其所以然！

否则今天出一门技术，就学习这种技术，明天出一种技术，又学习那一种技术，永远停留在简单使用别人的技术，调用别人暴露的接口。不会主动设计和定制更符合自己团队需求的框架或者工具库，这是 IT界 最低级的工种，属于只会使用，不懂原理、不会定制的人。

第二级别的工种就是能够理解别人的框架设计和原理，具备一定定制化能力的人，这种对别人的框架能够修修补补、做一些符合预期的更改的人，距离最高级别的工种，差的就是脱离别人的框架，自己做设计和开发的能力了。

最高级的能力是什么？

能够俯瞰别人的框架，懂得怎么快速入手使用，怎么深入阅读别人的源码，掌握扎实的底层技术和原理知识，具备统筹全局、做顶层设计和研制解决技术痛点的框架的能力。这种是属于第一等技术公民。

一个人能够认识到自己的无知和欠缺的知识，以及人生的方向，才能够知不足而后进。

怎么说呢，学习本来就是这样一个过程：首先是一头雾水，然后迷迷糊糊地扎进去，接着学会了使用，就觉得站在了上帝视角俯瞰全局，然后你又会感到手足无措，因为你底层的原理没有搞懂，核心的能力没有具备，你只是在整体上有了一个认知，你未搞明白的底层设计方法和原理才是真正硬核的有价值的东西，所以我们现在学到的东西都只是知识汪洋中的冰上一角。

一个人要想掌握真正有用的技能和能力，必须不断学习往下扎根技术、原理和设计，强化自身阅读优秀源码的能力，这些才是一个人在技术这条路上走得更远的关键。

英语、数学这两样知识在技术领域无处不在，编写代码、技术文档、算法设计、抽象事物结构等都是与这两门息息相关，一个人如果不懂这些好像也不会怎么影响他找工作，但是他一定接触不到一手资料，他的认知也局限于别人翻译过后得到的一种固化的语言思考方式带来的内容影响，简单点说就是，一种语言会塑造大脑不同的思维方式，一种语言会形成一种世界观，所以为什么说懂得双语的人，思维更发散和具有创意。

技术在精不在多，先抓住一门学精通，而后具备这种学通一门技术的感觉后，再学习其他技术也就相对更容易许多，而不是认为一门技术无从下手学会就放弃，那这样浅尝辄止的学习方式，对能力永远带不来质的飞跃。

强者都是在隐忍中强大，只要沉得住心，借助查阅百度、官方文档和AI辅助理解这些方式，专门集中精力研究一门技术，一段时间下来，一定会攻克很多问题，对整个技术框架的设计和原理融会贯通。

不要抱怨没有大佬带，自己成为大佬就是最现实的。每个人都很忙，没有人会为你负责，除了你自己。所谓的大佬，也不过是独自熬过了那些最艰难的岁月成长过来的。

沉得住气，扎得住根，才能往上爬，走得更远。任何想要追求捷径的方法，和自欺欺人的浅尝辄止的努力，都是最浪费时间的！只有脚踏实地的，把最阻碍你成长的硬骨头啃掉，后面的路才会越来越顺。

有时候，慢，是一种蓄势待飞，快，则意味着准备不佳。
